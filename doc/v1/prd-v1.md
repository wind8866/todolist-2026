## 1. 产品概述

### 1.1 背景

在日常生活中，用户存在任务管理混乱的问题，需要一款简单、轻量、可快速记录并持续跟踪待办事项的软件。

### 1.2 产品目标

提供一个可在线访问的网页应用，帮助用户完成任务记录、查看、筛选、编辑、完成、删除与排序。数据保存在用户当前设备的本地存储中，刷新页面后仍可恢复。

### 1.3 V1 核心价值

- 低成本记录待办事项
- 快速查看当前未完成任务
- 支持任务状态切换与排序调整
- 支持本地持久化，避免刷新后数据丢失

## 2. 范围定义

### 2.1 V1 交付范围

- 创建任务
- 删除任务
- 编辑任务
- 切换任务的完成状态
- 拖动排序
- 展示任务列表
- 搜索任务标题
- 切换“仅未完成 / 全部任务”视图
- 将任务数据持久化到本地设备

### 2.2 V1 不包含

- 移动端适配
- 云端同步
- 多用户与登录注册
- 任务分组且可共享给其他用户
- 垃圾箱和恢复功能
- 看板、本周、本月、时间线等更多视图
- 子任务、重复任务
- 备注、标签
- 统计分析
- 离线功能，冲突处理
- 提醒通知
- AI 自动分类与总结

## 3. 目标用户与使用场景

### 3.1 目标用户

希望通过工具进行计划管理、事务跟踪和执行安排的人。

### 3.2 核心痛点

用户无法及时记录脑中出现的待办事项，导致事项遗漏、优先级不清和进度失控。

### 3.3 典型场景

- 用户临时想到一件稍后要做的事，希望立即记录下来。
- 用户想查看今天有哪些任务待处理，以及哪些任务已过期。
- 用户想回顾哪些任务已经完成。
- 用户想通过拖动调整执行顺序。

## 4. 功能总览

### 4.1 页面结构

页面由以下区域组成：

- 顶部操作区域：添加任务按钮
- 筛选区域：搜索输入框、显示已完成复选框
- 列表区域：任务项列表
- 统计区域：未完成任务数量 / 任务总数量

### 4.2 功能清单

- 任务列表加载与本地回显
- 搜索与筛选
- 新增任务
- 编辑任务
- 切换完成状态
- 删除任务
- 拖动排序
- 空状态展示

## 5. 术语与约定

### 5.1 术语

- 未完成任务：`status = todo`
- 已完成任务：`status = done`
- 全部任务视图：包含 `todo` 和 `done`
- 默认视图：仅展示 `todo`
- 搜索状态：搜索输入框存在非空内容的状态

### 5.2 全局规则

- 列表按 `sortOrder` 降序展示，值越大越靠前。
- 新增任务默认插入列表最前。
- 页面每次发生有效数据变更后，必须立即同步到本地存储。
- 搜索仅作用于任务标题，采用大小写不敏感的模糊匹配。
- 搜索状态下不允许拖动排序。

## 6. 数据模型

### 6.1 任务对象定义

| 字段名      | 描述         | 是否必填 | 类型                      | 规则                                             |
| ----------- | ------------ | -------- | ------------------------- | ------------------------------------------------ |
| id          | 任务唯一标识 | 是       | string                    | 使用 uuid                                        |
| title       | 任务标题     | 是       | string                    | 必填，最长 100 字符                              |
| status      | 任务状态     | 是       | `todo` 、`done`           | 默认 `todo`                                      |
| priority    | 优先级       | 否       | `high` 、`medium` 、`low` | 可为空                                           |
| dueDate     | 截止日期     | 否       | string                    | 格式为 `YYYY-MM-DD`，仅在用户只选择日期时写入    |
| dueAt       | 截止时间点   | 否       | number                    | 时间戳，仅在用户选择了具体时间时写入             |
| createdAt   | 创建时间     | 是       | number                    | 新建任务时写入                                   |
| updateAt    | 最近修改时间 | 否       | number                    | 新建任务时、编辑任务或切换状态时更新；排序不更新 |
| completedAt | 完成时间     | 否       | number                    | 切换为 `done` 时写入；恢复为 `todo` 时清空       |
| sortOrder   | 排序号       | 是       | integer                   | 值越大越靠前                                     |

### 6.2 字段更新规则

#### 截止时间字段约束

- `dueDate != null` 且 `dueAt = null`：表示仅精确到日期。
- `dueDate = null` 且 `dueAt != null`：表示精确到具体时间。
- `dueDate = null` 且 `dueAt = null`：表示未设置截止时间。
- `dueDate != null` 且 `dueAt != null`：视为非法数据，不允许保存。

| 操作         | createdAt    | updateAt       | completedAt  | sortOrder            |
| ------------ | ------------ | -------------- | ------------ | -------------------- |
| 新增任务     | 写入当前时间 | 写入当前时间   | 为空         | 设为当前最大值 + 1   |
| 编辑任务     | 不变         | 更新为当前时间 | 不变         | 不变                 |
| 切换为已完成 | 不变         | 更新为当前时间 | 写入当前时间 | 不变                 |
| 切换为未完成 | 不变         | 更新为当前时间 | 清空         | 不变                 |
| 删除任务     | 删除数据     | 删除数据       | 删除数据     | 其余任务保持现有顺序 |
| 拖动排序     | 不变         | 不变           | 不变         | 根据拖动结果重算     |

### 6.3 排序规则

- 列表按 `sortOrder` 从大到小展示。
- 新增任务时，`sortOrder = 当前最大 sortOrder + 1`。
- 拖动排序后，系统按新的全量顺序重新分配 `sortOrder`，保证顺序稳定且刷新后不变。
- 在“仅显示未完成”视图中拖动时，拖动结果仍作用于完整任务列表，且拖动后的目标项在完整列表中应与当前参照项相邻。

### 6.4 状态规则

- `todo -> done`：任务标题变灰并增加删除线，写入 `completedAt`。
- `done -> todo`：移除灰色与删除线，清空 `completedAt`。
- 已完成任务不显示编辑按钮。

## 7. 功能规则

### 7.1 启动与数据加载

#### 目标

用户打开应用后，应看到当前设备本地已保存的任务列表。

#### 规则

- 页面初始化时读取本地存储。
- 若本地无数据，显示空状态“请添加任务”。
- 若存在数据，按 `sortOrder` 降序恢复列表。
- 统计区展示“未完成任务数量 / 任务总数量”。

### 7.2 搜索与筛选

#### 输入

- 单行文本输入框，placeholder 为“任务标题”
- `显示已完成`复选框

#### 规则

- 默认仅展示未完成任务。
- 勾选 `显示已完成` 后展示全部任务。
- 搜索输入为实时过滤，无需单独点击搜索按钮。
- 搜索采用标题模糊匹配，且不区分大小写。
- 搜索状态下不允许拖动排序。

#### 空状态优先级

- 当前存在搜索关键字且无匹配结果时，优先显示“过滤后无任务”。
- 当前无搜索关键字，且所有任务均已完成、列表又处于默认视图时，显示“所有任务已完成”。
- 当前无任何任务数据时，显示“请添加任务”。

### 7.3 任务列表展示

#### 每个任务项包含

- 状态复选框
- 标题
- 优先级标识
- 截止日期时间
- 删除按钮
- 编辑按钮（仅未完成任务显示）

#### 展示规则

- 标题在 `done` 状态下显示为灰色并带删除线。
- 优先级显示规则：
  - `high`：3 个红色叹号
  - `medium`：2 个橙色叹号
  - `low`：1 个蓝色叹号
  - 无优先级：不展示
- `dueDate` 有值时，截止信息只展示日期文案，不展示时间。
- `dueAt` 有值时，截止信息展示为“日期文案 + 空格 + 24 小时制时间”，例如“今天 18:30”“明天 09:00”。
- 日期文案按以下优先级判断，越靠前优先级越高：
  - 昨天、今天、明天：直接显示“昨天”“今天”“明天”。
  - 本周内其他日期：显示“周一”至“周日”。本周按周一开始、周日结束。
  - 今年内其他日期：显示“4月5日”这类格式。
  - 跨年日期：显示“27年4月5日”这类格式。
- 时间部分始终使用 24 小时制 `HH:mm`，例如“06:05”。
- `dueDate` 有值时，逾期判断以当天结束时间为边界；当前日期晚于 `dueDate` 时显示为红色。
- `dueAt` 有值时，逾期判断以 `dueAt` 为准；`dueAt` 早于当前时间时显示为红色。
- 未逾期且截止日期为今天时，截止信息显示为蓝色。

### 7.4 新增任务

#### 入口

点击“添加任务”按钮，打开新增弹窗。

#### 表单字段

- 标题：必填，最长 100 字符
- 优先级：选填，可选 `high`、`medium`、`low`
- 截止日期：选填，只选择到日期；保存后写入 `dueDate`
- 截止日期时间：选填，选择到具体时间；保存后写入 `dueAt`

#### 保存规则

- 标题为空时不可保存，并展示错误提示。
- 标题超过 100 字符时不可保存，并展示错误提示。
- 用户只能在“截止日期”与“截止日期时间”中二选一填写，不能同时填写。
- 仅填写截止日期时，保存 `dueDate`，并将 `dueAt` 置空。
- 仅填写截止日期时间时，保存 `dueAt`，并将 `dueDate` 置空。
- 截止日期时间若被选择，则不可早于当前时间。
- 保存成功后：
  - 创建新任务
  - 默认状态为 `todo`
  - 将当前时间写入 `createdAt` 和 `updateAt`
  - 插入列表最前
  - 写入本地存储
  - 更新统计信息
  - 关闭弹窗

### 7.5 编辑任务

#### 入口

用户鼠标移入未完成任务后，点击编辑按钮。

#### 规则

- 编辑弹窗字段与新增任务保持一致。
- 打开编辑弹窗时，需回显当前任务信息。
- 已完成任务不显示编辑按钮，不能进入编辑流程。
- 用户切换填写方式时，系统需自动清空另一种截止字段。
- 保存成功后：
  - 更新任务内容
  - 保留 `createdAt`
  - 更新 `updateAt`
  - 写入本地存储
  - 刷新列表内容

### 7.6 切换完成状态

#### 入口

点击任务项前方复选框。

#### 规则

- 点击后在 `todo` 和 `done` 之间切换。
- 切换为 `done` 时：
  - 标题变灰并增加删除线
  - 写入 `completedAt`
  - 更新 `updateAt`
- 切换为 `todo` 时：
  - 恢复正常样式
  - 清空 `completedAt`
  - 更新 `updateAt`
- 切换完成状态后，统计区需立即更新。
- 任务是否继续显示，取决于当前筛选条件。

### 7.7 删除任务

#### 入口

用户鼠标移入任务项后点击删除按钮。

#### 规则

- 点击删除后弹出确认框：`确认删除任务：<任务标题>？`
- 用户确认后执行物理删除，不可恢复。
- 删除成功后：
  - 更新列表
  - 更新统计信息
  - 写入本地存储

### 7.8 拖动排序

#### 前置条件

- 当前不处于搜索状态。

#### 规则

- 用户可拖动当前可见任务到目标任务前或后。
- 全部任务视图下，拖动后的顺序与界面所见顺序一致。
- 默认视图下，拖动作用于完整任务列表，而不是仅作用于可见的未完成子集。

#### 示例

- 原始完整顺序：`abcde`
- 其中：`b`、`d` 为已完成任务
- 默认视图可见顺序：`ace`
- 若将 `e` 拖到 `c` 之前，完整顺序变为 `abecd`
- 若将 `e` 拖到 `c` 之后，完整顺序变为 `abced`

## 8. 页面状态与交互约束

### 8.1 空状态

- 无任何任务：显示“请添加任务”
- 全部任务已完成且当前仅展示未完成任务：显示“所有任务已完成”
- 搜索或筛选后无结果：显示“过滤后无任务”

### 8.2 按钮显示规则

| 场景                   | 删除按钮       | 编辑按钮       | 拖动排序 |
| ---------------------- | -------------- | -------------- | -------- |
| 未完成任务，非搜索状态 | 鼠标移入后显示 | 鼠标移入后显示 | 允许     |
| 已完成任务，非搜索状态 | 鼠标移入后显示 | 不显示         | 允许     |
| 搜索状态               | 鼠标移入后显示 | 未完成任务显示 | 不允许   |

### 8.3 本地持久化规则

- 新增、编辑、切换状态、删除、排序后，必须立即写入本地存储。
- 刷新页面后，任务列表、状态、排序、优先级、截止日期时间均可恢复。
- V1 本地存储 key 固定为 `todolist:web:tasks`。
- V1 本地存储 payload 顶层包含 `schemaVersion: 1`，用于后续结构升级时的数据迁移判断。

## 9. 用户主流程

### 9.1 主流程

打开 App -> 读取本地任务数据 -> 展示默认待办列表 -> 用户执行新增、搜索、筛选、编辑、完成、排序或删除操作 -> 页面刷新列表与统计 -> 最新数据写入本地存储

### 9.2 关键子流程

#### 新增任务

点击添加按钮 -> 打开弹窗 -> 输入表单 -> 校验通过 -> 保存 -> 写入本地存储 -> 刷新列表

#### 编辑任务

鼠标移入未完成任务 -> 点击编辑 -> 修改表单 -> 保存 -> 更新任务并写入本地存储 -> 刷新列表

#### 切换状态

点击复选框 -> 状态切换 -> 更新字段与样式 -> 更新统计 -> 根据筛选条件刷新展示

#### 删除任务

鼠标移入任务 -> 点击删除 -> 二次确认 -> 删除并写入本地存储 -> 刷新列表

#### 排序任务

拖动任务 -> 放置到目标位置 -> 重算 `sortOrder` -> 写入本地存储 -> 刷新列表

## 10. 验收标准

### 10.1 基础加载与持久化

- 首次打开应用且本地无任务数据时，页面正常展示空状态，无脚本错误。
- 本地已有任务数据时，刷新页面后可正确恢复任务列表、状态、优先级、截止日期时间与顺序。
- 每次有效数据变更后，本地存储中的任务数据与界面展示保持一致。
- 若本地存储数据损坏或版本不支持，页面按无数据处理，不得出现阻塞使用的错误提示。

### 10.2 新增任务

- 点击“添加任务”后可打开新增弹窗。
- 标题为空时不可保存，且有明确提示。
- 标题长度超过 100 字符时不可保存，且有明确提示。
- 截止日期与截止日期时间不能同时填写。
- 仅填写截止日期时，任务按日期精度保存。
- 仅填写截止日期时间时，任务按时间精度保存，且不可早于当前时间。
- 保存成功后，任务出现在列表最前，默认状态为未完成。

### 10.3 编辑任务

- 仅未完成任务显示编辑按钮。
- 编辑弹窗需正确回显原任务信息。
- 保存成功后，任务内容与本地存储同步更新。
- 编辑操作会更新 `updateAt`。

### 10.4 搜索与筛选

- 搜索按标题模糊匹配，且不区分大小写。
- 搜索输入后，列表实时展示过滤结果。
- 默认仅显示未完成任务；勾选 `显示已完成` 后展示全部任务。
- 搜索无结果时显示“过滤后无任务”。
- 当前无搜索关键字且所有任务都已完成时，默认视图显示“所有任务已完成”。

### 10.5 切换完成状态

- 点击复选框后，任务可在已完成与未完成之间切换。
- 切换为已完成后，标题显示为灰色并带删除线。
- 切换为已完成时写入 `completedAt`；恢复为未完成时清空 `completedAt`。
- 切换状态后，统计区数值立即更新。

### 10.6 删除任务

- 鼠标移入任务项时显示删除按钮。
- 点击删除按钮后出现带任务标题的确认提示。
- 用户确认后，任务被物理删除且不可恢复。
- 删除后列表、统计值与本地存储数据保持一致。

### 10.7 排序

- 非搜索状态下，任务可拖动排序。
- 搜索状态下，不允许拖动排序。
- 全部任务视图下，拖动结果与界面顺序一致。
- 默认视图下，拖动结果在完整任务列表中的位置符合排序示例规则。
- 排序后刷新页面，任务顺序保持一致。

### 10.8 列表展示

- 任务列表按 `sortOrder` 降序展示。
- 优先级展示与规则一致。
- 仅设置 `dueDate` 的任务按日期展示；仅设置 `dueAt` 的任务展示日期与时间。
- 相对日期文案需按“昨天/今天/明天 -> 本周周几 -> 今年月日 -> 跨年短年份月日”的优先级展示。
- `dueAt` 的时间部分始终按 24 小时制 `HH:mm` 展示。
- 已逾期任务的截止信息以红色显示。
- 统计区始终正确展示“未完成任务数量 / 任务总数量”。

### 10.9 稳定性

- 连续新增、编辑、删除、切换状态、排序 100 次后，无页面报错且数据一致。
- 在最新浏览器环境下，核心功能可正常使用，宽屏布局无明显错位或遮挡。

## 11. 非功能需求

- 支持最新浏览器。
- 对宽屏样式进行优化。
- 保留创建时间与完成时间等关键时间。

## 12. 已冻结实现口径

- 截止日期相对文案按以下优先级判断：昨天/今天/明天 -> 本周周几 -> 今年内 `M月d日` -> 跨年 `yy年M月d日`。
- `dueDate` 只展示日期文案；`dueAt` 展示“日期文案 + `HH:mm`”。
- 本周以周一为起始日、周日为结束日。
- 本地存储固定使用 key `todolist:web:tasks`，payload 顶层版本号固定为 `schemaVersion: 1`。
