## 1. 目标

- 将 Todo List V1 从需求冻结、工程基建、功能开发、自测上线拆成可执行任务，降低遗漏规则与返工风险。
- 在 `pnpm workspace + Turborepo` 的单仓结构下先交付 Vue 3 Web 端，为后续接入后端项目与 React 项目预留扩展空间。
- 提前固定 TypeScript、ESLint + typescript-eslint、Conventional Commits、表单校验与时间处理等工程口径，避免开发期临时拍板。

## 2. 范围与交付物

### 2.1 本期必须交付的功能

- Web 端 Todo List V1，覆盖 PRD 约定的任务展示、搜索、筛选、新增、编辑、切换完成状态、删除、拖动排序、空状态与统计。
- 本地持久化能力，保证刷新页面后任务列表、排序、状态、优先级与截止时间可恢复。
- 基础工程能力：`pnpm workspace`、`Turborepo`、`Vite`、Vue 3、TypeScript。
- 基础规范能力：ESLint + typescript-eslint、Conventional Commits + commitlint + husky。
- 表单与时间处理基础能力：vee-validate + Zod、date-fns。
- 基础界面能力：原生 HTML + `@picocss/pico`，满足宽屏浏览器使用。

### 2.2 本期不交付的功能

- 后端服务、接口联调与数据上云。
- React 端项目与独立后端项目。
- 独立 `utils` package；V1 先在当前应用内组织类型与公共函数，后续再抽离。
- 第三方组件库接入。
- 移动端适配。
- PRD 中明确不做的能力：登录注册、多用户协作、云同步、子任务、标签备注、提醒通知、统计分析、垃圾箱、更多任务视图、离线冲突处理、AI 自动分类与总结。

### 2.3 交付物列表

- 可安装、可启动、可构建的 monorepo 工程骨架。
- Todo List V1 Web 应用代码与打包产物。
- 代码规范配置、提交规范配置与基础脚本命令。
- V1 文档集：PRD、技术设计、开发计划、自测记录。
- 已知问题记录与发布步骤说明。

## 4. 阶段划分

1. 需求冻结：确认 V1 交付边界、字段口径与验收标准，已固定“新增任务时当前时间写入 `createdAt` 和 `updateAt`”、本地存储策略与相对时间文案边界。
2. 技术设计：明确 monorepo 目录结构、Vue 3 组合式状态组织、本地存储方案、表单校验方案、时间展示规则与 `vue.draggable.next` 拖拽落地方案。
3. 基础能力开发：完成 workspace 根配置、Vite Vue 应用初始化、代码规范、提交规范与基础存储能力。
4. 核心功能开发：完成列表展示、搜索筛选、新增编辑、状态切换、删除、排序与基础样式整理。
5. 自测与修复：按 PRD 验收标准完成核心流程、边界场景与稳定性自测，并修复阻塞问题。
6. 发布上线：完成构建验证、已知问题登记、发布步骤整理与版本收口。

## 7. 风险与依赖

| 类型 | 内容                                                                           | 应对方式                                                                                     |
| ---- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| 风险 | 默认视图拖拽需作用于完整任务列表，排序规则实现复杂                             | 先抽纯函数处理完整列表与可见子集映射，再以 `vue.draggable.next` 接入 UI 交互并补排序自测用例 |
| 风险 | 相对时间文案虽已冻结，但周边界、跨年格式和时间拼接容易在实现中出现偏差         | 在 T9 中先实现独立格式化函数，并按固定样例补单元测试                                         |
| 风险 | 不使用组件库会增加弹窗、悬浮按钮、交互细节的手工实现成本                       | 先列交互清单，开发完成后按清单逐项回归                                                       |
| 依赖 | `localStorage` 采用稳定 key `todolist:web:tasks` + 顶层 `schemaVersion: 1`     | V1 按当前口径实现；后续若调整数据结构，在新版本补迁移逻辑                                    |
| 依赖 | 拖拽实现固定使用 `vue.draggable.next`，但仍需在 T10 前完成默认视图排序映射验证 | 先完成最小可行 Demo，再进入正式编码                                                          |
| 依赖 | 未来会拆出独立 `utils` package，但 V1 不单独创建 package                       | 当前先在应用内按 `types`、`utils`、`composables` 分层，保证可抽离性                          |

## 8. 当前开发就绪判断

- 当前已冻结的关键口径包括：任务字段规则、本地存储 key 与版本策略、相对时间文案边界、`vue.draggable.next` 拖拽方案。
- 当前文档足以支撑 T2 至 T9 直接进入开发。
- T10 进入正式编码前，仍建议先完成一个最小拖拽验证 Demo，重点验证默认视图下“未完成任务子序列”回写完整列表的算法正确性。
- 结论：可以进入开发阶段，且优先从工程骨架、任务模型、storage 模块和时间格式化函数开始。
