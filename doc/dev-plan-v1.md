## 1. 目标
说明这一版计划文档解决什么问题。

示例：
- 将 Todo List V1 拆成可执行的小任务，降低开发过程中遗漏规则和返工的风险。

## 2. 范围与交付物
待补充：
- [ ] 本期必须交付的功能
- [ ] 本期不交付的功能
- [ ] 交付物列表

示例：
- 本期交付 Web 端 Todo List V1。
- 交付物包括前端页面、文档、基础自测记录。

## 4. 阶段划分
建议按“完整功能闭环”划分，不要按零散组件划分。

模板：
1. 需求冻结
2. 技术设计
3. 基础能力开发
4. 核心功能开发
5. 自测与修复
6. 发布上线

示例：
1. 需求冻结：确认 `sortOrder`、筛选规则、弹窗字段。
2. 技术设计：确认数据结构和拖拽落地方案。

## 5. 任务拆解表
这是正文核心。每个任务都要能独立判断是否完成。

模板：
| 编号 | 任务 | 输入 | 输出 | 预计耗时 | 完成标准 |
| --- | --- | --- | --- | --- | --- |
| T1 | [待补充] | | | | |
| T2 | [待补充] | | | | |

示例：
| 编号 | 任务 | 输入 | 输出 | 预计耗时 | 完成标准 |
| --- | --- | --- | --- | --- | --- |
| T1 | 初始化项目骨架 | PRD | 可运行项目 | 2h | 本地可启动 |
| T2 | 实现任务数据模型与存储服务 | PRD、技术设计 | Task 类型与 storage 模块 | 2h | 刷新后数据可恢复 |
| T3 | 实现新增和编辑弹窗 | PRD | 表单与保存逻辑 | 4h | 校验、回显、保存正常 |

## 6. 完成标准
写整个版本的 Definition of Done，不是单个任务的完成标准。

模板：
- [ ] PRD 中的本期范围已开发完成
- [ ] 核心场景已自测通过
- [ ] 已知问题已记录
- [ ] 发布步骤可执行

示例：
- 搜索、筛选、新增、编辑、删除、切换状态、排序均已完成并通过自测。
